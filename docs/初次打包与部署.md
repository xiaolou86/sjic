# 初次打包与部署

在 Linux 打包机上打好交付包，运维拿压缩包到客户环境安装。客户服务器和客户 Jetson 都不放源码。

装完之后发新版本，见 [后续打包与升级.md](后续打包与升级.md)。

## 分工

| 做什么 | 在哪一台机器 | 这台机器上有什么 |
|--------|--------------|------------------|
| 构建平台镜像、打应用包、导出交付包 | Linux 打包机 | 仓库、Docker |
| 构建边缘镜像并导出 tar | 一台开发用的 Jetson | 仓库、JetPack 6、Docker、NVIDIA Container Runtime |
| 安装管理平台 | 客户服务器 | Docker（含 Compose 插件）、交付包 |
| 安装边缘程序 | 每台客户 Jetson | Docker、NVIDIA Container Runtime、交付包 |

客户机器不需要 Node、Python 或仓库。平台镜像在开发机上打成 Linux amd64，客户服务器用 x86_64。边缘镜像只能在 Jetson 上打。

## 1. Linux 打包机

正式交付使用 Git tag 作为唯一版本来源。先提交本次发布代码，再创建并推送 tag；例如：

```bash
git tag -a v1.0.3 -m "Release v1.0.3"
git push origin v1.0.3
```

Linux 打包机和 Jetson 构建机都检出同一个 tag。不要在 tag 提交上保留未提交修改。Makefile 会从当前提交的精确 `vX.Y.Z` tag 取版本，并检查工作区干净；tag 不存在、格式不符或有未提交修改时会停止。该版本会写入安装包及其中的 `VERSION` 文件，不会改写仓库里的 `backend/VERSION` 或 `edge-agent/VERSION`。

在仓库根目录操作。打包和导出都在 Linux 上做；边缘镜像仍需在 Jetson 上单独构建。

Linux 打包机检出本次 tag（以下以 `v1.0.3` 为例）：

```bash
git checkout v1.0.3
```

### 1.1 导出交付包

Jetson 构建好边缘镜像并把 `sjic-edge-jetson.tar` 拷到 Linux 仓库根目录后，在 Linux 上执行：

```bash
make release
```

该命令会构建平台运行时镜像、打两个应用安装包，并导出 setup 交付包。默认边缘镜像路径为仓库根目录下的 `sjic-edge-jetson.tar`；也可指定：

```bash
make release EDGE_IMAGE=/path/to/sjic-edge-jetson.tar
```

得到以下四个文件：

- `dist/sjic-platform-<版本>.tar.gz`
- `dist/sjic-edge-<版本>.tar.gz`
- `dist/sjic-platform-setup-<版本>.tar.gz`
- `dist/sjic-edge-setup-<版本>.tar.gz`

例如 tag 为 `v1.0.3` 时，实际文件名中的版本会是 `1.0.3`。应用包里是 Python 字节码和前端页面，没有 `.py` 源码。

把这两个文件交给运维。

## 2. Jetson 构建机

只用一台开发用的盒子打镜像。客户现场的盒子不做这一步。这台机器需要能访问外网，以便拉取 `ultralytics/ultralytics:latest-jetson-jetpack6`。

在 `edge-agent` 目录：

```bash
git checkout v1.0.3
docker compose build
docker save -o sjic-edge-jetson.tar sjic-edge:jetson
```

示例 tag 应替换为本次发布 tag。把 `sjic-edge-jetson.tar` 拷回 Linux 打包机，放在仓库根目录供 `make release` 使用。

## 3. 运维：客户管理平台

把本次生成的 `sjic-platform-setup-<版本>.tar.gz` 拷到客户服务器后执行（以下以 `1.0.3` 为例）：

```bash
tar -xzf sjic-platform-setup-1.0.3.tar.gz
cd sjic-platform-setup-1.0.3
sudo bash install.sh
```

脚本会导入镜像，把应用放到 `/opt/sjic/releases/1.0.3`，启动容器，执行数据库迁移，并启用升级服务 `sjic-updater`。

浏览器打开 `http://<服务器IP>:38880`。

| 端口 | 用途 |
|------|------|
| 38880 | 页面，以及边缘下载模型、安装包 |
| 38881 | API |
| 38883 | MQTT。边缘心跳、任务下发、升级指令 |

出厂账号：

| 用户名 | 密码 | 角色 |
|--------|------|------|
| super_admin | 123123 | 服务商 |
| admin | 123123 | 客户 |

未导入授权时可以登录，业务功能不可用。在「授权管理」复制机器码，签发后导入。说明见 [backend/docs/LICENSE_DEPLOYMENT.md](../backend/docs/LICENSE_DEPLOYMENT.md)。授权绑定宿主机 `/etc/machine-id`，重建容器不会使授权失效。

## 4. 运维：客户 Jetson

每台客户盒子做一次。盒子要能访问管理平台的 `38880`、`38881`、`38883`。镜像已经在交付包里，现场不用拉取基础镜像。

解压后先改 `config.yaml.example` 里的平台地址：

```yaml
architecture: "jetson"

mqtt:
  broker_url: "管理平台IP"
  broker_port: 38883

platform:
  api_base_url: "http://管理平台IP:38881/api/edge"
```

`edge_name` 留空时使用主机名。

```bash
tar -xzf sjic-edge-setup-1.0.3.tar.gz
cd sjic-edge-setup-1.0.3
sudo bash install.sh
```

脚本把示例配置复制到 `/opt/sjic/edge/config.yaml`（这个文件已存在则不覆盖），导入镜像并启动 `sjic-edge`。

安装时还没改地址的话，之后编辑 `/opt/sjic/edge/config.yaml`，再执行：

```bash
docker restart sjic-edge
```

看日志：

```bash
docker logs -f sjic-edge
```

出现心跳后，管理平台按本机 MAC 登记该节点。

## 5. 装完后的目录

管理平台：

```text
/opt/sjic/current -> /opt/sjic/releases/1.0.3
/opt/sjic/updater/          升级器与现场 compose
/opt/sjic/data/             数据库、模型、告警等
```

Jetson：

```text
/opt/sjic/current -> /opt/sjic/releases/1.0.3
/opt/sjic/edge/config.yaml
/opt/sjic/edge/models|alerts|logs
```

数据库、模型、告警、录像和边缘配置在升级时保留。下一版在 Linux 打包机上打出 `sjic-platform-<版本>.tar.gz` 和 `sjic-edge-<版本>.tar.gz`，运维在页面上传，不用再拿 setup 交付包或仓库到现场。
